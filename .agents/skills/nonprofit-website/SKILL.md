# Nonprofit Website

## Governing skill

Inherit `.agents/skills/nonprofit-operating-system/SKILL.md`. This skill narrows execution; it does not override the master contract.

## Mission

Build or improve nonprofit web experiences that reduce friction, increase trust, and produce measurable next actions without generic nonprofit or SaaS patterns.

## Before changing anything

Establish:
- primary user and situation;
- page purpose and primary question;
- primary action;
- required proof;
- entry source and expected exit;
- success metric;
- existing content/assets/routes/forms/analytics;
- what must not change;
- rollback path.

For brownfield work, inspect first and preserve working infrastructure.

## Preferred information architecture

Use **IDENTITY → HUMAN → BELIEF → PROOF → NEXT ACTION**.

Use fewer sections. Prefer real founder/community material over decorative modules. Do not use cards, stats, testimonials, or CTAs merely because a template expects them.

## Copy handling

Classify each block as KEEP VERBATIM, KEEP AND REPOSITION, REWRITE WITH APPROVAL, REPLACE WITH EVIDENCE, REMOVE, or MISSING AND REQUIRED.

Do not invent program names, claims, outcomes, testimonials, or community need.

## Conversion paths

Support only relevant paths such as:
- family/community;
- volunteer;
- partner/sponsor;
- donate;
- event/campaign;
- contact;
- email signup.

Every path must explain what happens next.

## Verification

Before calling work complete verify:
- mobile and desktop;
- forms and confirmation state;
- links;
- accessibility basics;
- analytics/event tracking where expected;
- performance regressions;
- production deployment;
- rollback target.

## Output

Report outcome in client language first. Technical implementation detail stays internal unless requested.
