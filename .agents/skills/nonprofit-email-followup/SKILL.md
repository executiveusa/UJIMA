# Nonprofit Email / Follow-up

## Governing skill

Inherit `.agents/skills/nonprofit-operating-system/SKILL.md`.

## Mission

Ensure important actions receive timely acknowledgment and a clear next step while keeping public-facing communication human, simple, and consent-aware.

## Standard pathways

### Family/community
registers or inquires → confirmation → reminder/details → event/service → thank-you → next opportunity

### Volunteer
expresses interest → acknowledgment → orientation/info → next opportunity → reminder

### Partner
inquiry → internal notification → follow-up → materials → meeting → next step

### Donor
contribution → thank-you → receipt/required record → impact follow-up → future campaign

## Writing rule

Use simple client and community language. Avoid automation jargon, overlong nurture sequences, generic inspiration, manufactured urgency, and claims not supported by evidence.

## Automation rule

SYSTEM DETECTS → SYSTEM PREPARES/SENDS low-risk operational follow-up → HUMAN CONFIRMS consequential messages.

Approval is required for sensitive public statements, major fundraising claims, legal/tax representations, controversial messaging, or consequential partnership commitments.

## Consent and deliverability

Respect consent state, unsubscribe requirements, sender identity, and existing email systems. Do not force Gmail/Google Workspace if the client prefers another system.

## Verification

Before calling a flow complete verify:
- trigger condition;
- correct recipient;
- content and links;
- reply-to/sender identity;
- duplicate-send behavior;
- consent/unsubscribe behavior where applicable;
- internal notification when needed;
- follow-up state written back to the CRM when in scope.

Client-facing result should describe what now happens automatically, not which automation tool was configured.
