# Scale-Positive Process

## Purpose
Turn every completed client outcome into a reusable operating capability without sacrificing truth, approval, quality, or ownership.

## Core loop

**LOCK → PRODUCE → REVIEW → APPROVE → PUBLISH → VERIFY → REUSE**

### 1. LOCK
Freeze the facts, strategy, visual system, ownership, approval rules, dimensions, naming, protected assets, and definition of done before production.

Required locks for ASC3ND social production:
- approved event facts
- approved content theme and posting date
- typography system
- palette roles
- A3 transparent logo placement
- platform dimensions
- no synthetic people for documentary/community storytelling
- approval owner
- publishing state defaults to draft

### 2. PRODUCE
Create the smallest bounded client-ready artifact using only locked inputs.

Rules:
- one output has one writer
- filenames are human-readable and date-first
- documentary video uses real ASC3ND source media
- no invented quotes, people, attendance, outcomes, or event scenes
- no silent production publishing

### 3. REVIEW
Run independent review before client approval.

Review dimensions:
- factual accuracy
- brand system compliance
- typography and composition
- mobile readability
- subtitle/crop quality for video
- accessibility/contrast
- consent/privacy where people appear
- grid/calendar fit

A builder cannot approve its own governed work.

### 4. APPROVE
Human approval is required before any governed publish action.

Approval must identify:
- artifact/version
- approver
- date/time
- requested changes or approval decision

No approval evidence = remain draft.

### 5. PUBLISH
Publish only the approved artifact to the approved account/time slot.

Rules:
- preserve posting order
- protect Instagram grid logic
- do not substitute an unplanned post without recalculating/preflighting the grid
- publishing adapters remain replaceable

### 6. VERIFY
Production is not complete when a publish API returns success.

Verify the live result:
- correct account
- correct media
- correct caption
- correct crop/cover
- correct link/CTA
- correct subtitles
- correct grid position
- no broken facts
- store evidence

If live verification fails, stop and repair or roll back.

### 7. REUSE
Only verified patterns become reusable system capability.

After verification:
- capture the template/token/workflow
- record what changed
- record failure modes
- convert repeated mechanical work into scripts/adapters
- convert repeated judgment into explicit review criteria
- keep client-specific facts in tenant configuration, not the reusable factory

## Scale-positive rule

**Do not scale output. Scale verified capability.**

A process is scale-positive when each client delivery leaves behind a better reusable system while preserving client ownership, human approval, and factual integrity.

## Artifact lifecycle

`idea → locked brief → draft → internal review → client review → approved → scheduled → published → verified → reusable pattern`

No state may be skipped for governed client work.

## ASC3ND video production implementation

For each scheduled Reel:
1. lock source footage and transcript range
2. write a dated edit brief
3. create a review composition in Descript
4. confirm 9:16 crop and mobile-safe subtitles
5. add approved ASC3ND end card/signature treatment
6. run consent/privacy and factual QA
7. obtain human approval
8. export/schedule
9. verify live
10. store edit decision, evidence, and reusable template

## Operating principle

Every client project should improve one or more of:
- template quality
- production speed
- QA reliability
- evidence quality
- approval clarity
- automation safety
- publishing reliability
- client independence

If work adds complexity without improving a paid/verified outcome or reusable capability, park it.
