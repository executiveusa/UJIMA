## Summary

The managed-agent support package is an optional, ongoing service providing active monitoring, prompt refinement, skill updates, and quarterly improvement cycles for the client's Mission OS agent configuration. It is separate from the maintenance package and not required to own or operate Mission OS.

---

## What this package is

After deployment, the client's AI agents are configured and running. Over time, programs change, staff needs evolve, and workflows shift. The managed-agent support package keeps the agent configuration aligned with the organization's current operations.

This is not autonomous AI management. Every change to agent configuration goes through Asc3nd's operator with client review before deployment. The client approves all substantive changes to their agents.

---

## What is included

### Agent health monitoring (monthly)
- Review of agent event logs and error rates via Mission OS event journal
- Review of approval queue patterns (what's getting approved, what's getting rejected, what's being flagged)
- Review of model usage against configured budgets
- Written health report delivered monthly

### Prompt and skill updates (on request, up to 4 per month)
- Client reports a workflow problem or desired behavior change
- Operator drafts updated agent prompt or skill configuration
- Client reviews the draft before deployment
- Operator applies approved changes to the agent pack
- Verification run after each change

### ICM workflow tuning (quarterly)
- Review of ICM stage contract usage and human gate patterns
- Identify stages where human review is taking longer than expected or producing rework
- Propose workflow adjustments — client approves all changes
- Apply approved adjustments and run verification

### Artifact review (quarterly)
- Review of artifacts generated by agents (draft grants, email drafts, social posts, etc.)
- Assess quality against client's standards
- Propose prompt adjustments to improve output quality
- Client approves before any agent prompt change is applied

### Quarterly improvement cycle (included)
- Full review of agent pack configuration against current organization priorities
- Identify gaps, unused capabilities, and new opportunity areas
- Propose an improvement plan — not automatically implemented
- Client approves plan before any changes are made
- Progress report delivered at end of quarter

### Priority incident response (business hours)
- Agent issues reported by client are triaged within 4 business hours
- Resolution plan provided within one business day
- Hot-fix applied if approved by client

## What is not included

- Autonomous agent operation (all sensitive actions require human approval — this is non-negotiable)
- New custom skill development (available as a separate engagement)
- System infrastructure maintenance (see Maintenance Package)
- Emergency response outside business hours
- Compliance audits or certifications
- Guaranteed agent output quality (outputs are drafts for human review)
- Grant writing services (agents draft, staff review and submit)

---

## What managed agents are and are not

**Managed agents are:**
- Configured AI agents running on the client's VPS
- Capable of drafting content, answering questions, and generating structured outputs
- Constrained by approval policies — risky actions require explicit human approval
- Updated only with client consent

**Managed agents are not:**
- Autonomous systems that act without human oversight
- Grant writers (they draft; staff review and submit)
- Legal advisors, financial advisors, or compliance officers
- Always-on systems that replace staff judgment

The client's Mission OS approval policy enforces hard blocks on:
- Grant submission
- Legal and financial filings
- Outbound messages to donors, funders, or community members
- Public publishing
- Cross-tenant data access

These blocks cannot be removed by the managed-agent support package. They are structural.

## How it works operationally

1. Monthly check-in: Asc3nd operator reviews agent health, usage, and approval patterns
2. Client submits change requests via agreed channel (email, Notion, or shared doc)
3. Operator drafts proposed changes and sends to client for review
4. Client approves or declines each change
5. Approved changes are applied by operator and verified
6. Monthly report delivered summarizing changes, health, and open items

The client retains full administrative control. Asc3nd does not modify agent configuration without client review and approval.

---

## What happens if the package is cancelled

Agents continue to run with their current configuration. The operator manual includes instructions for making basic agent configuration changes independently. Complex changes may require a new engagement.
