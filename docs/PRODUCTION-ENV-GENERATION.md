# Production Env Generation — Mission OS Phase 9 Staging

**Audience:** Operator generating credentials for a Hostinger VPS staging or production deployment
**Purpose:** Document safe credential generation, storage, and rotation without committing any real value to this repository
**Rule:** No secrets in git. No secrets in docs. No old demo keys. All production/staging credentials are freshly generated. `.env` files stay on the VPS only. `.env.example` files remain placeholder-only.

---

## Where credentials are generated

All credentials are generated **on the target VPS**, at deploy time, using the commands below. Nothing in this document contains an actual generated value — every example shows the command, never the output.

Do not generate production credentials on a local dev machine and copy them to the VPS over an unencrypted channel. Do not reuse any value that has ever appeared in this repository's git history — see the historical key note below.

## Required secret inventory

| Secret | Used by | Generation command | Rotation trigger |
|---|---|---|---|
| `POSTGRES_PASSWORD` | Postgres container | `openssl rand -hex 32` | Any suspected compromise; annually at minimum |
| `JWT_SECRET` | Mission API session auth | `openssl rand -hex 32` | Any suspected compromise; on operator offboarding |
| `DEMO_ADMIN_PASSWORD` | Initial admin login (demo/staging only) | `openssl rand -base64 24` | Before first real client login; disable demo account for production tenants |
| `MISSION_OS_OPERATOR_KEY` | Operator API auth | `node missionctl/missionctl.mjs operator-key create <slug> --label <name>` | Per-integration; rotate on staff offboarding |
| `HERMES_AGENT_KEY` | Hermes → Agent Service API auth | `node missionctl/missionctl.mjs operator-key create <slug> --label hermes-agent` | On Hermes redeploy or suspected compromise |
| `LITELLM_MASTER_KEY` | LiteLLM gateway admin auth | `openssl rand -hex 20` | Any suspected compromise |
| `WEBUI_SECRET_KEY` | Open WebUI session signing | `openssl rand -hex 32` | Any suspected compromise |
| `NEXTAUTH_SECRET` | Langfuse auth (NextAuth) | `openssl rand -hex 32` | Any suspected compromise |
| `LANGFUSE_PUBLIC_KEY` | Langfuse trace routing | Generated by Langfuse project settings (self-hosted UI) after first boot | On Langfuse project reset |
| `LANGFUSE_SECRET_KEY` | Langfuse trace routing | Generated by Langfuse project settings (self-hosted UI) after first boot | On Langfuse project reset |
| `PROVIDER_API_KEYS` (OpenAI, Anthropic, etc.) | LiteLLM upstream routing | From each provider's console — not generated locally | Per provider's own rotation policy; immediately on leak |
| `BACKUP_ENCRYPTION_KEY` | Encrypting offsite backup archives (if offsite backup is configured) | `openssl rand -hex 32` | Any suspected compromise; before re-enabling offsite backup after an incident |

## Generation examples

These are examples of the command shape only. Do not paste generated output into any tracked file, chat log destined for a shared doc, or commit message.

```bash
# 32-byte hex secret (JWT_SECRET, POSTGRES_PASSWORD, WEBUI_SECRET_KEY, NEXTAUTH_SECRET, BACKUP_ENCRYPTION_KEY)
openssl rand -hex 32

# 48-byte base64 secret (alternate format where base64 is preferred)
openssl rand -base64 48

# 20-byte hex secret (LITELLM_MASTER_KEY)
openssl rand -hex 20

# 24-byte base64 password (DEMO_ADMIN_PASSWORD)
openssl rand -base64 24
```

Run these directly on the VPS shell, or in a local terminal that discards output to a password manager rather than a file. Never redirect output to a file inside this repository's working tree.

## Where generated values live

| Location | Committed to git? |
|---|---|
| `handoff/<tenant>/managed/.env.managed` | No — gitignored (`handoff/*/managed/.env.managed`) |
| `handoff/<tenant>/managed/hermes/env` | No — gitignored |
| `handoff/<tenant>/managed/langfuse/env` | No — gitignored |
| `handoff/<tenant>/managed/litellm/env` | No — gitignored |
| `handoff/<tenant>/managed/open-webui/env` | No — gitignored |
| `mission-data/<tenant>/` (hashed operator keys) | No — gitignored |
| `.env.managed.example` (this repo) | Yes — placeholder values only (`change_me`) |

`scripts/secret-audit.mjs` enforces this at commit time by scanning all tracked files for key-shaped patterns and failing the build if a raw secret is found in a non-example file.

## Rules

- No secrets in git.
- No secrets in docs — this document and every other doc in this repository contain command shapes only, never real values.
- No old demo keys. Keys from commits at or before `500c13b` (see `docs/AGENT-PROVENANCE.md` Session 4b and `docs/SECURITY-CHECKLIST.md`) are non-production, revoked, and must never be reused or referenced as valid.
- All production/staging credentials must be freshly generated on the VPS at deploy time — never copied from a local `.env`, from this repository, or from a prior deployment.
- `.env` files stay on the VPS only. They are never uploaded to a shared drive, pasted into a chat, or committed.
- `.env.example` and `.env.managed.example` remain placeholder-only (`change_me`, `<GENERATED_BY_MISSIONCTL>`) forever — do not "fill in" the example file with a real value, even temporarily.

## Credential rotation checklist

Run this checklist on a schedule (recommended: quarterly) and immediately after any suspected compromise, staff offboarding, or before onboarding a new production tenant on a shared VPS.

- [ ] Generate new `POSTGRES_PASSWORD`; update `DATABASE_URL`; restart `postgres` and dependent services with zero-downtime plan or documented maintenance window.
- [ ] Generate new `JWT_SECRET`; this invalidates all existing sessions — notify staff before rotating.
- [ ] Rotate `MISSION_OS_OPERATOR_KEY` and `HERMES_AGENT_KEY` via `missionctl operator-key create`; revoke the old key; update any integration using the old key.
- [ ] Generate new `LITELLM_MASTER_KEY`; update LiteLLM container env; update any client referencing the old key.
- [ ] Generate new `WEBUI_SECRET_KEY` and `NEXTAUTH_SECRET`; this invalidates existing Open WebUI/Langfuse sessions.
- [ ] Rotate `LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY` from the Langfuse project UI; update env files referencing the old keys.
- [ ] Rotate any `PROVIDER_API_KEYS` per the provider's own console; revoke the old key at the provider.
- [ ] Rotate `BACKUP_ENCRYPTION_KEY` only after confirming all backups encrypted with the old key have been migrated or are no longer needed — decrypting old backups after rotation requires the old key.
- [ ] Run `node scripts/secret-audit.mjs` after rotation to confirm no rotated value was accidentally committed.
- [ ] Record the rotation date and reason in the VPS's own operator log (not in this repository).
