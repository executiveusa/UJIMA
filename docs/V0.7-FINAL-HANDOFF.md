## Vercel deployment note (duplicate-root issue)

The `apps/site` Next.js app is configured for Vercel deployment. If you configure Vercel via the Vercel dashboard and point it at the repo root instead of `apps/site`, you may see a build error: "No Next.js project found at root."

**Fix:** In Vercel project settings → Framework Preset → Next.js, set Root Directory to `apps/site`. Do not change the root `package.json` to accommodate Vercel — the monorepo is intentionally structured with the Next.js app at `apps/site`, not the root.

This is a configuration setting in Vercel, not a code change. Do not create a `next.config.js` at the repo root to work around it.

## What requires live credentials (Phase 9)

Before a live VPS deployment, generate fresh credentials for:

| Value | Where used | How to generate |
|---|---|---|
| `POSTGRES_PASSWORD` | Postgres container | `openssl rand -hex 32` |
| `JWT_SECRET` | API session auth | `openssl rand -hex 32` |
| `NEXTAUTH_SECRET` | Langfuse auth | `openssl rand -hex 32` |
| `LITELLM_MASTER_KEY` | LiteLLM gateway | `openssl rand -hex 20` |
| `WEBUI_SECRET_KEY` | Open WebUI | `openssl rand -hex 32` |
| `LANGFUSE_PUBLIC_KEY` | Langfuse trace routing | From Langfuse project settings |
| `LANGFUSE_SECRET_KEY` | Langfuse trace routing | From Langfuse project settings |
| `LITELLM_OPENAI_API_KEY` | OpenAI routing | From OpenAI platform |
| `LITELLM_ANTHROPIC_API_KEY` | Anthropic routing | From Anthropic console |
| `HOSTINGER_VPS_IP` | Caddy + DNS | From Hostinger VPS dashboard |

None of these appear in any tracked file. Generated env files go to `handoff/<slug>/managed/` which is gitignored. See `docs/PRODUCTION-ENV-GENERATION.md` for the full secret inventory, generation commands, and rotation checklist.

## What NOT to touch

- Do not change `.gitignore` rules for `handoff/*/managed/hermes/env` and similar — these block credential leakage
- Do not commit any file matching `handoff/*/managed/(hermes|langfuse|litellm|open-webui)/env` or `release-manifest.json`
- Do not commit `mission-data/` or `backups/`
- Do not use or rotate any key from commits at or before `500c13b` in the git history — those keys are non-production and invalid
- Do not rewrite git history (no `git push --force`, no `git rebase -i` on merged commits)
- Do not edit `apps/site` Vercel configuration via the dashboard in ways that break the monorepo root structure
- Do not add live API keys to any tracked file, `.env`, or configuration committed to version control
